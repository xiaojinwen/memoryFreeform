### 真正的 bug：scale 记忆 0.594 → 0.7（用户体感「窗口变大」）
LSPosed 日志实证：00:32:48 Birth 恢复 mark.via=0.594，00:33:06 重开恢复 0.7。
机制链：**Birth 注入丢失**（DOWN 快照读到实际 scale 已是 0.7=默认档）→ 用户**纯移动**窗口的
touched 帧（size-write 746 行 / onMovedByResize 828 行）调 maybeRecordScale 读到现值 0.7，
与记忆 0.594 差值超阈 → **把系统现值「合法化」写盘**。

### fix187 修法（三处，全部收口到「拉伸证据」）
1. 746 行 size-write 的 maybeRecordScale：加 downScale 快照比对（|d-fs|>SCALE_DRAG_EPS 才写）。
2. 828 行 onMovedByResize 的 maybeRecordScale：同上口径。
3. 1345 行 flushTerminalAsMove：`d0 == null ||` 改为 `d0 != null &&` —— 旧写法把「没证据」
   当成「拉伸了」，#1 采样重入时 downScale 已被 #0 remove，每次 #1 都会补写现值。
⇒ scale 写入的唯一依据 = 本次手势内 DOWN→当前读数真的变了。纯移动/关闭/注入丢失一律不写。

## fix190：调试浮层数据源纠错 —— 记忆必须读 Settings.Global，不能只读 /data/system 文件

### 用户提问（两个）
1. 「pos 和 mem 怎么会不同？不符合的位置不该设到 pos」
2. 「现在不是只有刚开机才读文件吗，后续都走内存？」

### 核实结论（HookContract.kt fix180/181，真读代码确认）
**三层存储，不是"开机读一次文件"**：
- 写：内存热层（rectMem/scaleMem）**即时** + Settings.Global**即时** + `/data/system` 文件
  **延迟 3s 防抖**（`scheduleFileFlush`；防抖会被连续操作一路重置 ⇒ 文件可能长时间停在旧值）
- 读：内存热层（300ms TTL）→ Settings.Global → 文件兜底（且会把旧文件回填 Global 做迁移）
⇒ 用户的理解「后续走内存」**方向正确**，但内存有 300ms TTL，过期会回落到 Global（即时写）；
  文件只是兜底且滞后，代表不了当前真值。

**pos ≠ mem 的合法来源（pos 是窗口当下真实 Task bounds，浮层只显示、不参与设置）**：
- 拖动中 / 抬手待判期还没落盘（fix186 单一写入时机）→ 短暂不同，正常
- **出生时被 `clampRect` 平移**（BirthHook：保持宽高、只平移位置）⇒ 记忆放不进屏幕时
  重开后 pos 与 mem 天然不等（这是设计，不是 bug）
- 关闭时 hook 拒收（fix184 `closingPkgs` 闸：关闭期间尺寸类写入全拒）→ pos 变、mem 不动
- ⚠ 之前还可能只是「文件滞后」造成的**假象**

### 修法（fix190，DebugOverlayService.kt）
- `readMap(path, globalKey)`：优先 `settings get global <key>`（真值、即时），为空才兜底读文件，
  返回 Pair(global, file)。
- 卡片新增差异标注：Global 与文件不一致时显示 `s 0.630 (文件 0.522)` / `mem 130,619 (文件 99,699)`，
  一眼区分「真没记住」还是「只是文件还没刷」。
- 编译：`!!` 冗余警告（IntArray 已非空）无害。

## ★★ fix191（重大）：live scale 读取一直是坏的 —— 方法名大小写错了

### 起因
用户：「改变大小的时候 scale 值变化很慢，不应该吧，看看 HyperCeiler 有没办法解决」。

### 取证：静态反编译本机 ROM 的 services.jar（~/.workbuddy/ref/rom/）
流程：`adb exec-out su -c cat /system/framework/services.jar > services.jar` → python zipfile 抽
classes*.dex → `grep -a` 定位含 `MiuiFreeFormActivityStack` 的 dex（classes3）→
`dexdump`（SDK build-tools 35.0.0，无参输出 52MB 类/方法清单）→ 扫方法名。
⚠ `dexdump -d`（反汇编）不含 Class descriptor 行，别用；`grep -a getFreeFormScale` 在 dex 里
**搜不到**（MUTF-8 前后有长度字节，子串匹配不稳定），要扫整个字符串池。

### 真身（本 ROM，静态实证）
- `com.android.server.wm.MiuiFreeFormManagerServiceStub.getFreeformScale(int taskId) F`
- `com.android.server.wm.Task.setMiuiFreeformScale(F) V`（+ Task 上 float 字段）
- `MiuiFreeformServiceStub.getFreeformScale(ActivityOptions)F / setFreeformScale(F,ActivityOptions)V`
- `MiuiFreeFormActivityStackStub` 是**空壳**（只有 <init>），本机命名是 `***Stub` 系列。

### 根因（-fix191 之前一直在犯）
我们读活值写的是 **stack.getFreeFormScale()**（大写 F、无参）—— 本 ROM **没这个方法**，
一直抛 NoSuchMethod ⇒ `freeformScaleOf()` 恒返回 NaN ⇒ **拖角改大小从来没被真正记下来过**。
（记忆文件里那些 0.594/0.63 是旧版本/出生注入留下的，不是拖角记的。）上游 HyperCeiler 靠
`ATMS.resizeTask` 监听缩放，**本 ROM 拖边角不走它**（探针 calls=0），所以照抄上游也没用。

### 修法
1. `freeformScaleOf()` 三级取值：Task float 字段（`mMiuiFreeformScale`/`miuiFreeformScale`…）
   → `manager.getFreeformScale(taskId)` → 老写法 ActivityStack 兜底（大小写两种都试）。
2. ★ **新增事件源**：hook `Task.setMiuiFreeformScale(F)` after —— 系统改缩放必经（拖边角逐帧、
   动画、出生注入都走），拿到就刷新 `liveScale`/`scaleCache`（顶掉 120ms 读缓存）
   ⇒ 任何一处再读都是最新真值，彻底解决"变化很慢"。
3. 新增 `HookContract.LIVE_SCALE_PATH=/data/system/memoryfreeform_live_scale` + `writeSnapshotFile()`：
   事件驱动、300ms 节流写快照（只给调试看，不参与任何记忆决策）。
4. 调试浮层加 `live` 行 = 系统当下真实缩放；`s` = 上次写盘的记忆值。两者分开看才能分清
   「没记住」还是「还没写」。

## fix192：关闭（手势 / 点 x）把缩放记成 1、以及移动后关闭位置错乱

用户报：① 移动位置后**手势关闭**小窗很容易出问题；② 移动位置后点小窗**操作栏 x** 关闭，
也会把缩放比记成 **1**。

### 取证
- `/data/system/memoryfreeform_live_scale`：`mark.via=1.0`、`com.coolapk.market=1.0`
  ⇒ 关窗动效确实把 freeformScale 还原成 **1.0**（退出小窗 = 缩放回 1）。
- 记忆 `memoryfreeform_window_scale` 里合法值全在 **0.56~0.79**（默认档 0.70）——
  1.0 从来不可能是"用户拉出来的大小"。

### 根因：缩放落盘**完全没有**关闭动效闸
- 点 x 关闭时：点按钮那一下刷新了 `lastTouchTs`（触摸证据成立）、`downScale` 里还留着
  上一轮手势的快照 ⇒ fix187 的"拉伸证据"（|down - now| > 0.01）**被绕过**，
  动效还原出的 `fs=1.0` 被合法写盘（`maybeRecordScale` 只挡 0.05~2.0）。
- 手势关闭时：`barUpJudge` 的判据 `reallyClosed = !alive && !visible` 太苛刻 ——
  关闭后 `isVisible` 未必立刻翻 false，`!alive && visible` 被判成"只是 mode 抖动、
  按移动处理" ⇒ `flushTerminalAsMove` 把**关闭动效帧**当移动落盘（位置错乱）。

### 修法（fix192，三处闸 + 判定口径）
1. 常量 `SCALE_MAX_SANE = 0.95f`：**缩放 ≥0.95 一律拒记**（1.0 = 退出小窗 / 老熟人假信号）。
2. `onScaleChanged`（`Task.setMiuiFreeformScale` 事件源）：`v ≥ SCALE_MAX_SANE` →
   **当场钉 closingPkgs + 清 downScale + cancelPending**。这是比"bounds 冲向全屏"更早更硬的
   关闭信号（用户不可能把小窗拉到 scale=1.0，那已是全屏）。
3. `maybeRecordScale` 三道闸：≥0.95 拒 / closingPkgs(3s TTL) 拒 / 窗口已非 freeform(mode≠5) 拒。
4. `onResize` 尺寸类回调里**在记缩放之前**加"关闭动效提前拦"：
   `非 resize && 非出生安静期 && bounds 相对基准明显变大 && 面积 ≥ 70% 屏` → 钉关闭、掐待写、
   作废 downScale、本帧什么都不记。（真拉伸一条都不占：拖边角改的是**缩放**，bounds 几乎不动。）
5. `flushTerminalAsMove` 两道闸：closingPkgs 命中 → 不写；全屏帧（≥屏-40）→ 不写。
6. `barUpJudge` #0/#1 判据统一改成 **`alive`（mode 明确 == freeform）才落盘**；
   `!alive` 一律不写（关闭态保留原记忆）。移动因此最多延后 1.6s（#1 复查）落盘，不会丢。
7. `downScale` 随窗口退出 freeform / onRemove / 判定结束一律清除（残留是误判的燃料）。

## fix193：拖角改大小「live 变了但 s（记忆）不变」

用户：调试浮层 `live` 值变了（0.5067 → 0.9076），但 `s`（记忆）没跟上。

### 探针实录（决定性）
```
397341 BAR-DOWN snapshot  coolapk                 downScale=0.5067
397609 SCALE-CHG tid=13996 v=0.64666665 bar=true  ← 拖动中缩放真被改了
397610 BAR-UP 开始 173                             （#0 采样排到 +700ms 才跑）
398012 BAR-DOWN snapshot                          downScale 被新手势覆盖成 0.6467 ★证据被抹掉
398311 BAR-UP 采样#0 … 未拉伸(down=0.64666665 now=0.64666665) → 不写
```
**根因**：`downScale` 是**单值**，下一次按下（BAR-DOWN）就把它覆盖成当下值；而抬手判定任务
排在 UP+700ms 才执行 ⇒ 执行时"按下值"已被刷新 = 当下值 ⇒ 差值为 0 ⇒ 判"没拉伸" ⇒ 不写。
fix186/187 那套「按下快照 vs 抬手读数」的比对法在这个时序下必然失效。

### 修法
1. ★ 新增 `dragScaled`（pkg→Boolean）：**锁存**证据。缩放已有事件源（fix191 的
   `Task.setMiuiFreeformScale`），只要在「正在拖」（`barFlags` 命中）时见到缩放被动过就置位，
   **中途多少次 DOWN 都抹不掉**；纯移动永不置位（挡假信号能力不变）。
2. 统一判据 `scaleDragEvidence(pkg, now)`：先认锁存位，再退回 downScale 比对。
   三个调用点（onResize / onMovedByResize / 抬手落定）全改用它；证据只在抬手落定处消费。
3. `onScaleChanged` 判「退出小窗」加 `!barFlags.containsKey(pkg)`：用户自己把小窗拉大时缩放
   同样升向 1.0（实测 live 到过 0.9076），那是真拉伸，不能当关窗动效。
4. ★ `onMFFSStartActivity`（出生）**无条件清 closingPkgs/downScale/dragScaled**：
   澎湃关小窗常不 remove Task ⇒ `freeformSeen` 一直留着 ⇒ onResize 的 `isFirstSeen` 永不为真
   ⇒ closing 标记清不掉 ⇒ 「关掉后 3s 内重开」的窗口移动/缩放全被"关闭中"闸拒收
   （探针 396454 `BAR-UP flush(移动) 窗口关闭中 → 不写`，而 396401 窗口已重开）。
5. barUpJudge 收尾、not-freeform、onRemove 一律清 `dragScaled`。
