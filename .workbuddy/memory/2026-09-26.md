## fix140：开窗时小窗四角闪直角（必现）—— 定位 + 修法

### 症状
打开小窗的瞬间四个角是**直角矩形**，约半秒后才"长"出圆角。用户报必现。

### 实测（真机 2304FPN6DC / HyperOS 3.0）
`dumpsys SurfaceFlinger` 逐帧采 task 图层（开窗后 ~500ms 内）：

```
Layer [16319] Task=12983#16319  bounds={286,714,1923.6,1042} scale 0.7000
  roundedCorner{33.4649}  t=…423602
  roundedCorner{58.9807}  t=…423721
  roundedCorner{63.0685}  t=…423805
  roundedCorner{67.1429}  t=…424022   ← 稳定
```
即圆角半径被**从 ~0 补间到 67.14**，约 500ms ease-out。

### 机制（★ 长期有效，别再重新挖）
- 澎湃 freeform 圆角 = **SurfaceFlinger 图层属性** `roundedCorner`（+ 父层 `drawFreeformEffect`），
  打在 task/leash 图层上，父层圆角向下传给子层，所以整窗被裁圆角。App 侧没有任何 drawable。
- 稳定值 **67.1429 = 47 / 0.70**：47px = `18dp`（`MiuiFreeFormManagerService
  .getMiuiFreeformCornerRadius()` 里 `applyDip2Px(18.0f)`；mini 小窗是 12dp），0.70 = 图层缩放。
  与 `MiuiPipImpl.setCornerRadiusForPipTask`、`TransitionImpl.buildFinishTransactionForTarget`
  里的 `cornerRadius / scale` 同款。
- 补间在 **SystemUI（pid 7950，WMShell）**：
  `MultiTaskingTransitionHandler → MiuiFreeformModeAnimation`，folme 动画引擎，
  每帧 `transaction.setCornerRadius(leash, folmeRadius / folmeScaleX)`。
  冷开走 `startMoveToFrontAnimation`（animationType 13，rotateX -90°→0° 翻入），
  喂的是 `addProperty(FOLME_RADIUS, cornerRadius)` **单值重载**，起点取 folmeControl 当前值
  （新 task = 0）⇒ 照样 0→47。
  ⚠ `startFullScreenToFreeformAnimation`（type 16）才是显式的 `addProperty(FOLME_RADIUS, 0f, cornerRadius)`；
  两条路都要覆盖。
- **这是澎湃给"打开小窗"设计的入场动画的一部分，任何方式开小窗都走**，不是
  `am start-activity --windowingMode 5` 引入的（logcat 实证冷开走的是 moveToFront 那条）。

### 修法（fix140）
新增 `hook/FreeformCornerHook.kt`，装在 **com.android.systemui**：
拦截 `MultiTaskingFolmeState.addProperty`，让 `FOLME_RADIUS` 起点 = 终点：
- 三/四参 `(prop, from, to[, ease])`：`from<=0 && to>0` ⇒ `from = to`；
- 两参 `(prop, to)`：先把 `mFolmeControl.setFolmeRadius(to)` 顶上去 ⇒ 动画变 47→47。

按「类名+方法名+参数形态」反射匹配（不硬编码签名），全程 runCatching，
总闸 `memoryfreeform_hook.off` + 单独开关 `memoryfreeform_corner.off`，
自检落盘 `/data/system/memoryfreeform_corner.state`。

⚠ **需用户在 LSPosed 里手动勾选 `com.android.systemui` 作用域并重启**
（manifest `xposedscope` 仍只声明 `android`，不敢改是为了避免解析失败丢现有作用域）。

## fix143：fix140 没生效的真因 —— SystemUI 作用域没勾（★ 教训）
用户反馈"还是会闪"。取证：
- `/data/system/memoryfreeform_corner.state` **不存在**；
- LSPosed 日志 `/data/adb/lspd/log/modules_*.log` 只有 `SingleHand/hook installed in android`
  （uid 1000 pid 2898），**没有任何 systemui 记录** ⇒ 钩子一行都没跑。
原因：fix140 只在代码里装了钩子，manifest `xposedscope` 仍是 `android`，SystemUI 要用户手动勾。

★ 结论（长期）：**LSPosed 的 `xposedscope` 必须用 resource 数组形式才会预勾** ——
`<meta-data android:name="xposedscope" android:resource="@array/xposed_scope" />` +
`res/values/arrays.xml` 里 `<string-array name="xposed_scope">`（android + com.android.systemui）。
纯 `android:value="包名"` 字符串 LSPosed 不解析，等于没声明。
排查手法：`cat /data/adb/lspd/log/modules_*.log | grep "installed in"` 看模块进了哪些进程。

### fix143 改动
1. 新增 `app/src/main/res/values/arrays.xml`，manifest 改 resource 形式 → LSPosed 预勾 systemui。
2. `FreeformCornerHook` 加**兜底钩子**（folme 那条依赖 MIUI 私有签名，ROM 一改就挂空）：
   挂 `android.view.SurfaceControl$Transaction.setCornerRadius`，判据
   **原始值递增 + 调用栈含 miuifreeform/multitasking**：
   - 只抬递增段（入场 0→5→20→33→…→67）；递减段（关闭 47→12、缩迷你窗）放行，不破坏退出动画；
   - `raw >= target*0.95` 的帧记为 `stable` 自适应；target 初值 = `18dp / 0.70`（density 现算）。
   - WeakHashMap 记 per-SurfaceControl 上次原始值（**加锁**，动画可能多线程）。
3. 自检文件新增 `clampSites` / `clamped` / `stable` 字段；`installed` 仍指 folme 挂点数。
   ⚠ 现在"两个点都没挂上也会落盘写 state"，方便排查作用域问题。

## ★★ fix144：真因推翻 —— 是我们自己的 BirthHook 造成的，不是澎湃

用户一句"不去 hook 系统的时候是不会闪的"推翻 fix140 结论。真机对照（关总闸 vs 装 hook）：

| 状态 | 开窗时圆角采样最小值 |
|---|---|
| hook 关闭（总闸 on） | 14.9 / 18.8 / 33.4 → 稳定 67.14（**照样补间**）|
| hook 生效 | 5.86 / 3.17 → 67.14 |

**两边都在补间，差别在补间时窗口有没有同时缩放**：
- 不 hook：窗口从默认尺寸**缩放**到小窗尺寸，圆角同步长 → 自然变形，看不出闪；
- 有 hook：BirthHook 让窗口**出生即最终尺寸**，尺寸不动、只有圆角 0→67
  ⇒ 头几帧就是直角矩形。
复用已有 task 转小窗也一样闪（3.17），因为 BirthHook 每次都写 launchBounds。

### fix144 解法：system_server 侧抢 leash，高频写终值盖掉补间帧
新 hook `FreeformCornerKeeperHook.kt`（装 system_server，作用域已有）：
leash 是 system_server 建的，拿到后用 5ms 间隔写终值 67.14、持续 900ms；
SystemUI 每 16ms 写补间值，被我们盖掉。缩放/位移/透明度不受影响。
拿 leash 的三个挂点（互为兜底）：
1. `SurfaceAnimator.createAnimationLeash`（老写法，返回值即 leash）；
2. ★ `WindowContainer.makeAnimationLeash()` —— **Android 15/16 真写法**，
   返回 `SurfaceControl$Builder`（不是 SurfaceControl！第一版挂错这里，kept=0）；
   ThreadLocal 记 builder + 它的 WindowContainer；
3. `SurfaceControl$Builder.build()` —— 认领上面 builder 的产物即 leash，
   用 WindowContainer 判 windowingMode==5，避免给全屏窗口乱加圆角。

⚠ 数值坑：`Resources.getSystem().displayMetrics.density` 在 system_server 里是
**3.5**（真机逻辑密度 2.625），算出来 90 而不是 67.14。改优先反射
`MiuiFreeFormManagerService.getMiuiFreeformCornerRadius / getFreeformScale`，
兜底用实测稳定值 **67.1429**。

`MiuiFreeFormBirthHook` 应用几何成功后调 `markBirth()`（时间窗兜底）。
自检 `/data/system/memoryfreeform_corner.state`：`keeperSites/seen/kept/radius`。
状态：1.0.144 已构建，**尚未真机验证（adb 掉线）**。判据：kept>0、radius≈67.14，
且采样最小 roundedCorner 接近 67 而不是个位数。

### fix146（修"圆角有点奇怪"）
用户反馈：不闪了但圆角怪。真机采样抓到 **`335.714` / `235`** 这种巨大半径 ——
根因是兜底钳制的 `stable = max(stable, raw)` **无上限学习**：某个全屏动画的 235
被当成"稳定值"，随后小窗每帧被抬成 235（SF 显示 235/0.7=335.7）。
修法：`stable` 只在 **[30,120] 区间**内学习（小窗量级），target 也 coerceIn(30,120)；
另补一条：入场头几帧 `raw==0`（纯直角）也抬上去（新增计数器 `zero`）。

### fix147（★ 弹簧过冲，真正的"圆角怪"）
计数器暴露：冷开几次后 `stable` 从 67.14286 漂到 **70.879105**。
原因：**folme 是弹簧动画，会过冲**（66.4 → 68.6 → 回落到 67.14），
而 `stable = max(...)` 把过冲峰值当成了稳定值 ⇒ 之后每帧被钉成 70.88，
比设计值大一圈（用户看到的"圆角有点奇怪"）。
修法：学习上限锁到 `defaultTarget()*1.02`（≈67.5），过冲帧一律不认。
实测：`stable=67.14286` 稳定、`clamped=99`、采样只剩 46.5~48（闪屏层，scale 1.0）
与 66.4~68.6（小窗层）→ **不再出现个位数/直角帧**。

## 用户补充观察（重要，解释"为什么有时看得见有时看不见"）
- **原生澎湃自己也会有一瞬间直角**（关 hook 采样最小 14.9/18.8/33.4）—— 圆角补间是
  系统固有行为，不是我们引入的；只是原生同时有尺寸缩放动画，视觉上被"自然变形"掩盖。
- **亮色内容下看不出来，深色/暗色内容才明显**：闪的是同一件事，能否看见取决于
  窗口四角与背后内容的**对比度** —— 暗色内容时方角露出的背景更扎眼，亮色时几乎融为一体。
- 推论：修法只能是**把圆角钉住**（fix147 已做），而不是靠降低补间幅度；钉住后
  亮/暗两种内容都不会再出现方角。
- 若暗色下仍有残留，下一个嫌疑对象是**闪屏层**（SnapshotStartingWindow，实测半径
  46.5~48、scale 1.0）—— 它走的是 `window_animation` 而非 miuifreeform 栈，
  兜底钳制 `isFreeformAnimStack()` 会主动跳过它。真要治就把这条判据放宽。

## ★ fix149：splash 屏第二个半径没钳 → 残留方角（已真机验证通过）
fix148 冷开采样抓到：**frame1 splash 屏 `{67.4842, 11.1818}`** —— X 被钉成 67.48
（=defaultTarget 67.5，证明确实走了我们的钳制），但 Y 还在 11.18 补间到 67（frame4 才到位）。
根因：`setCornerRadii(SurfaceControl, float, float, float, float)` 有 **4 个半径参数**，
旧 `clamp()` 只改 `args[1]`（第一个），其余 3 个没钳 ⇒ splash 的第二对角短暂露方角。

修法：`clamp()` 改成先 `radii = (1..n).mapNotNull{ args[it] as? Float }` 收集所有半径，
用 `radii[0]` 作判据（prev/递增/学习，与旧逻辑一致），需要改写时 `rewrite()` 把
`args[1..n]` 全部设为 target；学习用 `radii.max()`。数组形 `setCornerRadii(sc, float[])`
因 `args[1]` 非 Float 自动跳过（安全）。
