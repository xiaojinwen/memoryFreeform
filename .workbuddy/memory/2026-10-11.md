## fix195：记录钩子架构重写（fix66~194 状态机整体作废）

### 用户报的两个症状（本机连不上 adb，装机验证延后）
1. 拖角改大小**有时候**不保存；
2. 手势条**短快速上划**关闭小窗 → 位置错误。

### 根因（旧架构结构性缺陷，非参数问题）
- **症状①**：缩放写入依赖手势证据链（downScale 快照 / dragScaled 锁存 / 抬手消费），
  证据的置位、消费、清除分散在 5 处，任何时序错开（mode 抖动、#0/#1 重入、DOWN 覆盖
  快照、DOWN 时 freeformSeen 未登记）就丢一次写入。
- **症状②**：#0 采样（UP+700ms）无法区分「稳定活着」与「正在关闭动效中」。**上划甩出**
  动画只改位置不改面积 ⇒ 旧版全部"面积变大/全屏帧"闸不命中 ⇒ 动效中间帧被当"移动"落盘；
  fix186 又删了回滚 ⇒ 污染值无人纠正。

### 新架构（MiuiFreeformRecordHook.kt 全量重写，2352→约1050 行）
两条独立链路，状态只有 6 个容器（freeformSeen / barFlags / lastUpTs / upBounds /
pendingScale+scaleTasks / boundsTasks）：
- **链路 S（大小）**：唯一写盘门票 =「拖动期间的事件流」（barFlags 命中，或 UP 后 1.2s
  弹簧余波）。事件流 debounce 400ms 终值复验落盘（值域 <0.95 + mode==5 复验）；
  拖动中 150ms 节流实时写（fix194 要求保留）。**没有事件 = 永不写** ⇒ 纯移动不写
  （根除"注入丢失把 0.7 合法化"）、冷开动画不写（不再需要 isTouched）、
  关窗动效 1.0 被值域闸挡 + 清 pending。
- **链路 P（位置）**：resize 类回调**只登记不写**；bounds 唯一写入时机 = UP 后判定：
  当下 bounds vs **UP 时刻快照**四边差 ≤24px 才写，否则推迟（最多 3 次）；
  判定时 mode≠5 → 关闭不写。**短快上划关闭结构性修复**：+700ms bounds 在飞 → 推迟 →
  下一拍 mode≠5 → 不写。
- **关闭 = 清 pending，永不写**：无 closingPkgs/TTL/回滚（writeSnapshotAsClose、
  downScale、dragScaled、barSnapshot、barRecent、userGeomPkgs、lastSize、latest 全删）。
- resize 回调里 not-freeform 帧**不再取消任何 pending**（fix168b mode 抖动由判定任务的
  mode 复验消化）。
- 删除死代码：ATMS.resizeTask 挂点（本机 getFreeFormScale 大写 F 方法不存在恒 skip，
  且其监听的缩放变化必经 setMiuiFreeformScale 事件源）。
- 保留设施：挂点 5 站点、pointer listener（fix78e 实现）、MFFS.onStartActivity 注入、
  默认几何学习（fix124）、SB 迁移（fix79）、探针/自检文件、clamp 落盘口径
  （fix164/166/177）、调试浮层数据源（live_scale 快照 + Global/文件）不变。
