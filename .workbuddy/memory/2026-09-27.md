## fix168：尺寸记忆丢失（拉伸后关窗 → 重开变回原大小）
用户报「没有记忆大小」。真机取证（`tools/dev_size_diag.sh` + 受控 input swipe / am task resize）定位：
- **证据 1**：`am task resize` 改了窗口几何（bounds 变），但 `Task.resize ... skip=resize(skip-write)`、
  **记忆文件不变**——尺寸类回调（onResize/setBounds/resize）的 size-write 强依赖 `isTouched`（2s 内
  PointerEvent DOWN）。系统/App 的 resize 无触摸 → 不写（这是 App 主动 resize 到记忆值、不该覆盖记忆的正确行为）。
- **证据 2**：手动拖窗口（input swipe 命中窗口体）被识别为**移动**，BAR-UP 判移动 flush 终帧 → 写盘正常
  （`WRITE MAIN com.miui.calculator=302,600,1102,1400`）。移动链路 OK。
- **根因**：拖右下角缩放把手**拉伸**时，拖动期间（bar-drag → `scheduleWrite MOVE`）已即时落盘拉伸后新尺寸；
  但**关窗（退出 freeform）**走 `writeSnapshotAsClose`，原样写「按下快照」（拉伸前的旧尺寸）→ **覆盖刚记下的
  新尺寸** → 用户观感「拉伸后关窗，重开又变回原大小」=「没有记忆大小」。
- 修复（`MiuiFreeformRecordHook.writeSnapshotAsClose`）：关闭自愈**只回滚坐标、保留尺寸**——写盘用
  `Rect(snap.left, snap.top, snap.left+outSize.w, snap.top+outSize.h)`，`outSize` 取 `lastSize`（最近落盘尺寸，
  拉伸后已更新），无则退回记忆尺寸；坐标仍回滚到手势前停稳位置（防关闭动效帧污染）。移动场景 size 不变→等价无损。
- versionCode/Name 167→168，构建中。待装+重启+真机验证（移动不破坏；size 写入用 am task resize+tap 验证；
  拉伸后关窗是否保留尺寸需真机手测或尽量命中 handle 复现）。
- **真机复现出的真正根因（fix168b）**：上面那版只修了"覆盖时保留尺寸"，但没修"误判关闭"本身。
  抓 record.state.moved 发现：手动拖动窗口（input swipe）触发的 onMovedByResize 全 `bar-pending buffered`，
  松手后 BAR-UP 采样到 `getWindowingMode()=1`（非 freeform）→ **误判"关闭"** → writeSnapshotAsClose
  用按下快照覆盖 → 记忆的位置/尺寸全丢（窗口明明只是被拖动、am stack list 还在）。`mode` 在
  **拖拽释放/关闭动效瞬间会抖动成 1**，单凭它判关闭会把正常移动/缩放当成关闭。
  **修复**：barUpJudge 增加 `isVisible` 二次判据，`reallyClosed = !alive && !visible`——窗口仍可见就
  绝不判关闭、按移动 flush 终帧（含新尺寸）；只有 mode≠freeform 且 isVisible=false（澎湃关小窗=
  mode→fullscreen+隐藏）才是真关闭。移动/缩放的终帧现在能被正常写下，不再被快照回滚。
  fix168 两处互补：① barUpJudge 不再误判关闭；② writeSnapshotAsClose 即便真关闭也只回滚坐标保留尺寸。

  每次验证前用 `su -c 'sed -i ...'` 恢复 127,505,1207,2233 再测，避免污染结论。
