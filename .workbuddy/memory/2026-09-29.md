## fix185：拖动小窗移动位置后「有时候没记录」——fix183 回归（撤回其一半）

### 现象（用户报）
拖动小窗移动位置时，位置**有时候**没有记录（重开回到旧位置）。

### 根因：fix183 的一半改错了
fix183 为修「短快滑动关闭后位置错乱」做了两处改动，其中第二处是**错的治疗**：

- ✅ **保留** —— `bar-pending` 缓冲块上移到 size-write 分支之前：
  待判期内（barRecent 置位）的帧一律只缓冲不落盘，挡住关闭动效帧从 size-write 分支写盘。
  这才是修「关闭位置错乱」的真正功臣。

- ❌ **撤回** —— fix183 把 `#0` 采样（UP+700ms）的 `flushTerminalAsMove` 推迟到 `#1`（+2.3s）。
  当时注释假设「拖动中 bar-drag 已实时写，延后 1.6s 无害」，**两个前提都错**：
  1. 抬手后的**落定帧**（惯性滑行结束、窗口弹到最终位置）发生在 `barFlags` 已清除之后，
     走不到 bar-drag 段，只能靠这次 flush 落盘 —— 别无他路。
  2. `#1` 入口有令牌校验 `if (barRecent[pkg] != upTs) return`。这 1.6s 里用户再碰一下小窗
     （新手势覆盖 barRecent）或 onRemove 清掉 barRecent，都会让 flush **永不执行**
     ⇒ 拖完抬手，位置根本没进记忆。这就是「有时候」（取决于抬手后 2.3s 内有没有再碰）。

### 修法（fix185）
1. **撤回 `#0` 不落盘**：`attempt == 0` 且 `!reallyClosed` → **立即 `flushTerminalAsMove`**，
   再照常 postDelayed `#1` 复查。移动当场落盘，不再有 1.6s 脆弱窗口。
2. **关闭动效防护仍由两处承担**（都不需要推迟落盘）：
   - ① fix183 的 bar-pending 缓冲块（挡 size-write）；
   - ② `#1` 若判关闭 → `writeSnapshotAsClose` 用按下快照**覆盖**刚写的动效帧
     （自愈只回滚坐标、保留尺寸，fix168）。
3. **补洞**：`barUpJudge` 原 `val s = freeformSeen[pkg] ?: return` 会让关闭自愈在窗口已消失时
   彻底失效 ⇒ `#0` 写下的动效帧**永远没人回滚**（关闭错乱的另一半根因）。
   改为 `s == null` 时（令牌仍有效 = 窗口消失但未走 onRemove 清理）按「已关闭」自愈：
   `writeSnapshotAsClose(pkg)` 后 return。真 remove 时 onRemove 已清 barRecent，
   令牌校验会先 return，不会误触。

## fix186：**架构重构** —— 取消「拖动中实时写 + 关闭时回滚」，改为单一写入时机

用户一次提了三个互相打架的问题，并要求"互相规避好"。
诊断结论：**问题不在参数，在架构。** 旧做法是"写—回滚"模式：
拖动过程中实时往记忆里写跟指帧，等判定为关闭手势时再用「按下快照」去回滚覆盖。
这个模式天生脆弱 —— 回滚依赖 #0/#1 两段采样 + 令牌，任一时序错乱就污染；不回滚就丢失。

### 三个症状 → 三条根因
1. **拖左右下角改大小，有时能记忆有时不行**
   freeformScale 只在 touched 帧里**实时采样**（bar-drag / onResize / onMovedByResize 三处）。
   拖角时它是一个带弹簧动画的连续量，实时采到的常常是**动画中间值**而非用户拉出的最终值。
2. **手势关闭小窗，很大概率位置也变了**
   写进去的跟指帧靠 writeSnapshotAsClose 回滚，而"按下快照"本身未必干净 ——
   DOWN 那一刻窗口可能正在系统重摆（[35,127] 那一族），于是把污染值写成了用户位置。
3. **拖动移动位置，有时候没记录**
   (a) DOWN 时会 `runnables.remove()+latest.remove()` 把上一轮排好的落盘**直接抹掉**；
   (b) `barUpJudge` 的令牌校验 `barRecent[pkg] != upTs → return` 让旧判定永久作废。
   两者叠加 ⇒ 连续操作时前一次手势的位置彻底丢失。

### 新架构（三条一律作废旧逻辑）
**唯一写入时机** = 抬手 +600ms 判定为「移动」后，读**实时几何 + 最终缩放**落一次。
- 拖动中：`bar-drag` 只缓冲，**不再 scheduleWrite / maybeRecordScale**（← 总根）。
- 抬手 #0 仍 freeform → `flushTerminalAsMove`（写 bounds，并写 scale）。
- 判为关闭 → **什么都不写**。既然从未写过跟指帧，记忆里留着的就是手势前的参照位置，
  ⇒ 不需要任何回滚 writeSnapshotAsClose 的角色就此消失（4 个调用点全部改为不写 + 清理状态）。
- 仍排 #1 复查：万一 #0 的 closed 只是 mode 抖动（其实是移动），#1 会把正确几何补上。
- 取消令牌校验；（ Because 关闭不写，不再存在"旧快照盖新窗口"的风险，多次 flush 幂等）
- `barFlags` 15s 保险丝超时时改走 `barUpDecide`（UP 丢失也能补记），不再只是丢标记。
- 缩放安全阀：新增 `downScale`（按下时快照）+ `SCALE_DRAG_EPS=0.01f`，
  只有「按下 vs 抬手两次读数真的变了」才认定是用户拉伸并落盘。
  必须加 —— `maybeRecordScale` 的区间守卫挡不住 1.0，那正是记忆里反复警告的
  `getScale()` 假信号值（fix105 误信过，把窗口改得巨大）。

### 状态
- 版本 `versionCode=186 / 1.0.186`，`assembleDebug` **BUILD SUCCESSFUL**
  （仅 793/795 行旧代码「Unnecessary safe call」警告，无害）。
- 设备离线，**未装机、未 commit**。
- `writeSnapshotAsClose` 已零调用（仅剩定义 + 注释），暂留以便回滚；确认稳定后可删。
